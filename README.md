# Concurrent Web Scraper

Консольная утилита на Go: принимает список URL, скачивает страницы последовательно и конкурентно, выводит таблицу результатов (статус, размер, заголовок страницы, время ответа) и сводную статистику. Нужна, чтобы наглядно сравнить два подхода и показать, как безопасно собирать данные из горутин.

## Возможности

- Последовательный и конкурентный обход списка URL с замером общего времени
- Таймаут на каждый запрос (по умолчанию 5 с)
- Ограничение числа одновременных запросов (семафор на 5 слотов)
- Ошибки (DNS, отказ соединения, таймаут, обрыв чтения) не роняют программу, а попадают в таблицу
- Успехом считается ответ со статусом 2xx без ошибки. 404 и 500 идут в неуспешные
- Сводка: число успехов и ошибок, самая медленная страница, суммарный размер
- Список URL из файла (пустые строки и строки с `#` пропускаются) или встроенный набор по умолчанию

## Требования

Go 1.25 или новее (используется `sync.WaitGroup.Go`).

## Запуск

```bash
# встроенный список URL, таймаут 5 секунд
go run .

# список из файла и свой таймаут
go run . -file=./urls.txt -timeout=3s
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-file` | пусто (встроенный список) | файл со списком URL, по одному в строке |
| `-timeout` | `5s` | таймаут одного запроса (`500ms`, `3s` и т. д.) |

Пример `urls.txt`:

```
# учебные сайты для скрапинга
https://books.toscrape.com
https://quotes.toscrape.com
https://example.com
https://go.dev
https://localhost:1
```

## Результат: последовательно и конкурентно

| Режим | Общее время |
|---|---|
| Последовательно | 8.4 – 9.8 с |
| Конкурентно | ≈ 5.0 – 5.1 с |

Конкурентная версия работает примерно столько, сколько самый медленный запрос, а не сумму всех. В этом наборе самый долгий запрос это `httpbin.org/delay/10`, который обрывается по таймауту на 5 секундах. Поэтому 5 секунд это не предел горутин, а потолок, заданный одним медленным URL. На списке без «зависающих» сайтов выигрыш получается ещё заметнее.

## Как это устроено

- **Запись в `results[i]` без мьютекса.** Слайс результатов создаётся заранее нужной длины. Каждая горутина пишет только в свою ячейку `results[i]`, и двух горутин на одной ячейке нет. Порядок результатов совпадает с порядком URL.
- **`Stats` под `sync.Mutex`.** Счётчики успехов, ошибок, суммарный размер и самая медленная страница общие для всех горутин. `s.ok++` это три шага (прочитать, прибавить, записать), поэтому без блокировки инкременты теряются. `Add` берёт `Lock` и снимает его через `defer Unlock`.
- **`WaitGroup`.** `main` ждёт завершения всех горутин через `wg.Wait()`, и только после этого читает результаты и печатает статистику.
- **Семафор на буферизованном канале.** `sem := make(chan struct{}, 5)` пропускает не больше 5 запросов одновременно, чтобы не перегружать сайты и не упереться в лимиты системы.
- **Свой `http.Client` с таймаутом.** У стандартного клиента таймаута нет, и один зависший сервер повесил бы горутину навсегда.
- **Статус проверяется отдельно от ошибки.** `err == nil` не значит успех: ответ 404 приходит как обычный `resp`.

## Проверка

```bash
# детектор гонок (флаг -race относится к go, поэтому стоит до аргументов программы)
go run -race . -file=./urls.txt -timeout=5s

# статический анализ
go vet ./...
```

## Ограничения и идеи для развития

- Горутин запускается столько же, сколько URL, а семафор лишь ограничивает число одновременных запросов. Для больших списков лучше Worker Pool с фиксированным числом воркеров.
- Нет повторных попыток при временных ошибках и ограничения частоты запросов к одному хосту.
- Заголовок извлекается регулярным выражением. Для сложного HTML надёжнее использовать HTML-парсер.
- Вывод только в консоль. Можно добавить экспорт в JSON или CSV.
