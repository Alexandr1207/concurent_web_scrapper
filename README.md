# Concurrent Web Scraper v2 (Worker Pool + context)

Консольная утилита на Go: принимает список URL, скачивает страницы пулом воркеров и выводит таблицу результатов (статус, размер, заголовок страницы, время ответа) и сводную статистику. Вторая версия проекта: вместо «горутина на каждый URL + семафор» используется Worker Pool, а остановка запуска управляется через `context`.

## Возможности

- Worker Pool: заданное число воркеров берёт URL из общей очереди
- Таймаут на каждый запрос (`-timeout`, по умолчанию 5 с)
- Общий таймаут на весь запуск через `context.WithTimeout` (`-total`, по умолчанию 30 с)
- По истечении общего таймаута запросы в полёте прерываются, новые не раздаются
- Результаты возвращаются в том же порядке, что и URL в списке
- Ошибки (DNS, отказ соединения, таймаут, обрыв чтения) не роняют программу, а попадают в таблицу
- Успехом считается ответ со статусом 2xx без ошибки. 404 и 500 идут в неуспешные
- URL, до которых запуск не дошёл из-за общего таймаута, помечаются `not started`
- Сводка: число успехов и ошибок, самая медленная страница, суммарный размер
- Список URL из файла (пустые строки и строки с `#` пропускаются) или встроенный набор по умолчанию

## Требования

Go 1.21 или новее. Только стандартная библиотека.

## Запуск

```bash
# встроенный список URL, 5 воркеров, таймаут запроса 5 с, общий таймаут 30 с
go run .

# список из файла, 10 воркеров, общий таймаут 10 с
go run . -file=./urls.txt -workers=10 -total=10s
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-file` | пусто (встроенный список) | файл со списком URL, по одному в строке |
| `-workers` | `5` | число воркеров пула (значение меньше 1 завершает программу с ошибкой) |
| `-timeout` | `5s` | таймаут одного запроса (`500ms`, `3s` и т. д.) |
| `-total` | `30s` | общий таймаут на весь запуск |

Пример `urls.txt`:

```
# учебные сайты для скрапинга
https://books.toscrape.com
https://quotes.toscrape.com
https://example.com
https://go.dev
https://localhost:1
```

## Результат: число воркеров

Запуск на тех же 8 URL, `-total=30s`:

| Воркеров | Общее время |
|---|---|
| 1 | ≈ 9.7 с |
| 5 | ≈ 5.4 с |
| 10 | ≈ 5.0 с |

С одним воркером время равно сумме всех запросов. С пятью и десятью оно упирается в самый медленный запрос: `httpbin.org/delay/10` обрывается по таймауту на 5 секундах. Разница между 5 и 10 воркерами в пределах шума, потому что URL всего 8 и лишние воркеры простаивают. Сеть при замерах нестабильна: в двух прогонах `gobyexample.com` не уложился в таймаут, поэтому число успехов может отличаться.

## Как это устроено

- **Worker Pool.** `runPool` запускает `-workers` воркеров. Каждый в цикле `for j := range jobs` берёт задачу, вызывает `fetch` и отправляет результат в канал `results`.
- **Раздатчик задач.** Отдельная горутина отправляет URL в `jobs` и закрывает канал (`defer close(jobs)`). Если контекст отменён, она перестаёт раздавать задачи.
- **Закрытие `results`.** Закрывает отдельная горутина после `wg.Wait()`, то есть когда все воркеры закончили. Закрыть раньше нельзя: воркеры ещё пишут, а отправка в закрытый канал вызывает панику.
- **Порядок результатов.** В задачу и в результат добавлен индекс (`Id`, `JobId`). Основная горутина читает `results` и кладёт ответ в `out[JobId]`, поэтому порядок совпадает с порядком URL, а мьютекс для слайса не нужен.
- **`Stats` под `sync.Mutex`.** Счётчики, размер и самая медленная страница общие для всех воркеров. `s.ok++` это три шага (прочитать, прибавить, записать), поэтому без блокировки инкременты теряются.
- **`context`.** `fetch(ctx, client, url)` строит запрос через `http.NewRequestWithContext`, поэтому отмена контекста прерывает запрос в полёте. Общий таймаут задаётся один раз в `main` через `context.WithTimeout`.
- **Свой `http.Client` с таймаутом.** У стандартного клиента таймаута нет, и один зависший сервер повесил бы воркера навсегда.
- **Статус проверяется отдельно от ошибки.** `err == nil` не значит успех: ответ 404 приходит как обычный `resp`.

## Проверка

```bash
# детектор гонок (флаг -race относится к go, поэтому стоит до аргументов программы)
go run -race . -file=./urls.txt -workers=5 -total=10s

# общий таймаут короче, чем нужно для списка
go run -race . -workers=1 -total=3s

# статический анализ
go vet ./...
```

## Ограничения и идеи для развития

- Нет повторных попыток при временных ошибках и ограничения частоты запросов к одному хосту.
- URL со статусом `not started` не учитываются в сводке: статистику обновляют только воркеры.
- Нет аккуратной остановки по Ctrl+C (можно обернуть контекст в `signal.NotifyContext`).
- Заголовок извлекается регулярным выражением. Для сложного HTML надёжнее использовать HTML-парсер.
- Вывод только в консоль. Можно добавить экспорт в JSON или CSV.
